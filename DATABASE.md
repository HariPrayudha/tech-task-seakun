# Database Design

## 1. Database choice

Use MySQL in Docker Compose and Prisma ORM 7.10.0 as the ORM and migration tool. The connection string is provided through `DATABASE_URL`. Prisma Client uses the MySQL/MariaDB driver adapter.

## 2. Product model

Logical model:

| Field | Type | Rules |
|---|---|---|
| `id` | UUID string | Primary key, generated by the application/ORM |
| `name` | varchar | Required, trimmed, non-empty |
| `description` | text nullable | Optional |
| `price` | decimal(12,2) | Required, greater than or equal to 0 |
| `stock` | int unsigned | Required, greater than or equal to 0 |
| `category` | varchar nullable | Optional, trimmed |
| `imageUrl` | varchar nullable | Relative local path, not a binary blob |
| `createdAt` | datetime | Generated on creation |
| `updatedAt` | datetime | Updated automatically |

The initial schema intentionally stays close to the coding test and does not add inventory history or user ownership.

## 3. Indexes

Recommended indexes:

- `createdAt` for default list sorting.
- `updatedAt` for update sorting.
- `category` for category filtering.
- `name` for common ordering and search support.

The first implementation may use a case-insensitive `contains` query supported by the MySQL collation. Full-text search is unnecessary for this scope.

## 4. Data handling rules

- Convert and validate incoming numeric values before persistence.
- Never store a negative price or stock value.
- Keep the database price precision at two decimal places.
- Return `price` as a JSON number from the API, normalizing Prisma Decimal values explicitly.
- Store only a relative image path such as `/uploads/<generated-filename>` in `imageUrl`.
- Do not store image binary content in MySQL.

## 5. Migration and seed policy

- Prisma migrations are the source of truth for schema changes.
- Local Docker startup must run the documented migration command before the backend depends on the schema.
- Seed data is optional and should be safe to run repeatedly if added.
- Schema changes require updates to `API_SPEC.md`, this file, and `DECISIONS.md` when they alter public behavior.
