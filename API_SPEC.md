# API Specification

## 1. Conventions

- Base URL in local development: `http://localhost:3000`
- Content type for JSON endpoints: `application/json`
- Content type for image upload: `multipart/form-data`
- IDs are UUID strings.
- Dates are returned as ISO 8601 strings.
- Monetary values are returned as JSON numbers with up to two decimal places.
- The API uses the endpoint paths required by the coding test without an additional version prefix.

## 2. Success response shapes

Single resource:

```json
{
  "success": true,
  "data": {
    "id": "uuid",
    "name": "Keyboard",
    "description": "Mechanical keyboard",
    "price": 750000,
    "stock": 12,
    "category": "Accessories",
    "imageUrl": "/uploads/product-uuid.webp",
    "createdAt": "2026-09-11T00:00:00.000Z",
    "updatedAt": "2026-09-11T00:00:00.000Z"
  }
}
```

List resource:

```json
{
  "success": true,
  "data": [],
  "meta": {
    "page": 1,
    "limit": 10,
    "totalItems": 0,
    "totalPages": 0
  }
}
```

## 3. Error response

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": [
      {
        "field": "price",
        "message": "Price must be greater than or equal to 0"
      }
    ]
  }
}
```

Expected error codes include `VALIDATION_ERROR`, `NOT_FOUND`, `INVALID_IMAGE`, `UPLOAD_TOO_LARGE`, and `INTERNAL_SERVER_ERROR`.

## 4. Endpoints

### GET `/products`

Query parameters:

- `page`: positive integer, default `1`.
- `limit`: positive integer, default `10`, maximum `100`.
- `search`: optional name search string.
- `category`: optional category filter.
- `sortBy`: `name`, `price`, `stock`, `createdAt`, or `updatedAt`; default `createdAt`.
- `sortOrder`: `asc` or `desc`; default `desc`.

Returns paginated products and metadata.

### GET `/products/:id`

Returns one product. Returns `404` when the product does not exist.

### POST `/products`

Creates a product from JSON. The image is uploaded separately after the product is created.

Request body:

```json
{
  "name": "Keyboard",
  "description": "Mechanical keyboard",
  "price": 750000,
  "stock": 12,
  "category": "Accessories"
}
```

Returns `201` with the created product.

### PATCH `/products/:id`

Updates one or more product fields. `PUT` may be supported as an alias if implementation needs it, but the frontend should use `PATCH`.

Returns `200` with the updated product.

### DELETE `/products/:id`

Deletes the product and attempts to remove its local image file. Returns `204` with no response body on success.

### POST `/products/:id/image`

Accepts one multipart file using the field name `image`.

Rules:

- Allowed MIME types: `image/jpeg`, `image/png`, and `image/webp`.
- Default maximum size: 5 MB.
- A successful replacement updates `imageUrl`.
- The old local image is removed after the new image is safely stored.

Returns `200` with the updated product.

### GET `/uploads/:filename`

Serves locally stored image files as static assets. Filenames must be generated by the backend and must not allow path traversal.

## 5. HTTP status mapping

- `200`: successful read, update, or image upload.
- `201`: successful product creation.
- `204`: successful deletion.
- `400`: malformed request or invalid business input.
- `404`: product or resource not found.
- `413`: image exceeds the configured size limit.
- `415`: unsupported image type.
- `500`: unexpected server error.
